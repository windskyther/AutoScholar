## 已确认的停止原因

最后一条响应调用 `submit_code_ready`，JSON 格式正确，结束标识为 `tool_calls`，未被截断。
其 `summary` 为 **336 字符**，超过 Snapshot 本地工具 schema 的 **240 字符**上限。
DeepSeek 兼容层投影发送 schema 时省略不受支持的 `maxLength`，同时保持原始本地校验。
本地因此抛出 `llm_invalid_tool_call / tool_schema_violation`，没有暴露可执行的工具调用。

错误发生在 provider 返回结果前，未进入 Coding 节点已有的 Snapshot 参数反馈循环。
当前评测包装器只允许特定协调器阶段的有界原生 JSON 纠错，因此将该异常记录为 `provider_error` 并停止；
这是本地拒绝不合规响应的分类，不代表 HTTP 服务不可用。第三组仍保留 `task_success=null`。

通过实际 SDK + Mock HTTP 重放保存的原响应，稳定复现相同字段、240 字符限制和错误码，
保留原响应 SHA-256 与 5594 token 收据；**诊断新增供应商调用为 0**，没有改写响应或重评历史任务。
这也说明，下一步应为此类已收到且用量已知的 schema 错误接入 Coding 的有界纠错路径，
同时保留 240 字符、整批拒绝、工具执行前校验和调用预算；不能靠放宽限制或跳过校验解决。
本轮未实施该后续修复，也未开启修复后的付费复验。
