# 2026-10-28：收紧 Snapshot 输出并拒绝截断工具响应

针对 v8 Coding 大段重写、返回两条编辑且第二条被截断的问题，缩小单次输出范围，
并明确拒绝所有被标记为截断的原生工具完成。**本轮只有免费验证，没有新增供应商调用。**
旧 [v8 实测停止结果](2026-10-28-v8-live-result.md)及其七次调用保持原值，Phase 10 总验收未完成。

## 行为变化

- Snapshot 使用聚焦的源码就绪检查提示，不再重复拼入不可信的子计划文本。
  用户目标、完整源码和配置继续原样提供；缺少需求或验证失败仍须修改和审查。
- 每轮要求原生工具输出，仍只能执行一个调用。既有三个工具名称保持不变，参数限制为：
  `edit_file` 的 old/new 各最多 1024 字符，`create_file` 内容最多 2048 字符，
  就绪摘要最多 240 字符；整组参数序列化后最多 **4096 个 UTF-8 字节**。
- 限制同时进入工具 schema 和服务端校验。超限、额外字段、错误类型或空匹配文本在任何
  写入前拒绝，不截断参数、不部分执行；沿用原有一次有界协议纠正及共享预算。
- 通过参数检查的小编辑仍须预检写入后的完整源码请求，保留 1024 字节反馈预留。
  请求不适合派发时文件保持原值；没有绕过原 32768 字节请求上限。
- 原生工具响应只要 `finish_reason=length`，无论 JSON 是否恰好完整，都返回
  `llm_response_truncated`，不交出任何可执行调用。返回用量仍计费入账，`retryable=false`。
  普通纯文本响应及非 Snapshot Coding 的工具参数范围和批处理保持既有行为。
- 静态检查、pytest、实验及 Reviewer 仍执行。就绪声明不会替代这些检查；
  不增加 12 次模型调用、8192 输出额度、八次编辑或实验修复预算。
