# Phase 10 必要收尾：v13 完整真实配对范围

用户在明确剩余两项工作后要求“开始把必要的执行”：本轮直接执行一次完整 15 组真实配对，再进行证据审计、报告及最终组合验证。
不增加单独的 12 次付费预检，不扩大到多模型、大样本或长时间训练。

## 固定清单

| 场景 | 配置（从左到右串行） |
|---|---|
| normal | baseline、no_planner、no_reviewer、no_memory、no_replanning |
| recover | baseline、no_planner、no_reviewer、no_memory、no_replanning |
| deception | baseline、no_planner、no_reviewer、no_memory、no_replanning |

使用 [Coding schema 有界纠错修复](2026-11-03-coding-schema-feedback-fix.md)后的同一冻结运行时，生产源码不再更改。
每组新建任务和记录；不把 v12 的两组通过观测拼入本轮。原 951 个文件摘要及 v12 已消耗声明必须受保护。
使用独立 `live-paired-v13-claim.json`、授权账本和清单，不能更换批准编号来重置已用额度。

- 最多新增 **180 次物理 LLM、0 次 Tavily / Semantic Scholar**，每组最多 12 次；一次纠错同样计入预算。
- 每组 token 阈值 120000，最后一次响应可越过阈值；单次输出最多 8192，请求最多 32768 UTF-8 字节。
- 沿用当前模型、终端与兼容模式；金额没有可核验单价时保持未知。不切换供应商，不自动 HTTP 重试或整组重跑。
- 使用公开封闭语料、预置模板及 CPU MNIST 128/128 样本、一次 epoch 的工程子集；只发送公开目标、schema、源码及测试证据。
- 密钥仅用于认证；不发送 `.env` 文件、密钥内容、本地设计文档或应用数据库，不提交本地运行记录。

## 有限验收条件

正常、恢复基线须分别完成闭环和预定恢复；伪造指标基线须实际训练并被独立 oracle 拒绝。
关闭重规划的恢复负对照须触发故障后按规则停止，不进行第二次训练。
各变体的干预、源码/模型/资源身份、原始用量和清理检查均须成立。
消融组的任务失败可以是有效观测；不要求移除某组件一定变差或统计显著。
供应商错误、未知/不一致用量、基线/执行门槛不成立或冻结绑定变化则停止后续派发，保留未执行和未知结果。

四个对比各需要同版本三个场景的完整配对，报告真实差值、精确检验及 Holm 校正。
三个异质工程场景不能证明组件普遍收益；试验仍不覆盖开放网络研究或从零代码生成能力。

本轮完成后只做必要的免费收尾：核对历史工程/语义检索/供应商证据与新配对记录、生成最终 `evaluation_report.md`，
并验证评测模块与 main 的最终组合树。真实配对若未完成，不宣告 Phase 10 总验收通过。
既有脚本中的旧 `phase10_overall_acceptance=false` 是原范围的冻结输出，不通过重写历史文件改变它。
