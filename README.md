# AutoScholar

AutoScholar 是运行在本机的 AI 研究工作台。创建项目，添加模型连接，再围绕你的目标检索论文、阅读网页或分析项目 PDF，获得带引用的报告。

顶部 Dock 可在“项目与任务”“模型管理”“用量统计”之间切换。项目以卡片呈现，点击名称即可进入；界面跟随系统使用浅色或深色外观，并适配窄屏。

## 启动

安装 Docker Desktop 和 Node.js 24.x。Docker Desktop 及其数据保留在 D 盘。

首次使用，在项目目录执行：

```powershell
Copy-Item .env.example .env
notepad .env
```

填写以下配置，真实密钥只保存在本机 `.env`，不要上传到 GitHub：

| 配置 | 用途 |
| --- | --- |
| `MODEL_ENCRYPTION_KEY` | 加密已保存的模型 API Key，不用于登录或请求鉴权；升级时保留原值。 |
| `SANDBOX_MANAGER_TOKEN` | 隔离执行环境的独立凭据，至少 32 字符，与其他密钥不同。 |
| `TAVILY_API_KEY` | 可选，启用网页检索。 |
| `SEMANTIC_SCHOLAR_API_KEY` | 可选，论文检索留空时使用匿名接口，可能受到共享限流。 |
| `LLM_TIMEOUT_SECONDS` | 模型请求等待时间，默认 180 秒，最多 600 秒。 |

可运行两次以下命令生成两个不同的随机凭据：

```powershell
[Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
```

然后双击根目录 **[Start-AutoScholar.cmd](Start-AutoScholar.cmd)**。启动器会启动后台、打开工作台，浏览器刷新后也会自动连接。它不会自动提交任务。

手动启动可在项目根目录运行：

```powershell
docker compose up -d
```

另开窗口：

```powershell
cd web
npm ci
npm run dev
```

打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。依赖没有变化时，后续不必重复 `npm ci`。更新后台代码后需要重新构建镜像：`docker compose up -d --build`。

## 添加模型

所有语言模型都必须在顶部 Dock 的“模型管理”中添加。填写：

- 配置名称：方便自己识别，例如“论文阅读模型”。
- API 接口地址：服务商提供的 OpenAI 兼容基础地址，通常以 `/v1` 结尾，不要追加 `/chat/completions`。
- 模型名称：服务商提供的模型 ID。
- API Key：对应服务的密钥。

模型需要支持原生工具调用并返回 Token 用量。可保存多组连接，新建任务时自由选择。`.env` 不再提供默认语言模型，未选择已启用模型的请求会被拒绝。

API Key 加密保存在本机数据库，保存后不会回显，重启后仍可使用。保存配置不调用模型，不产生 API 费用。停用配置只影响新任务；更换密钥或模型时添加一组新配置。备份数据库时也要妥善保管 `MODEL_ENCRYPTION_KEY`。

添加模型时可选填每百万 Token 的普通输入、缓存命中输入和输出单价，选择人民币或美元。不填写则不估算费用；缓存单价留空时按普通输入计价。更换单价时添加新配置，已有调用保留原价格。

## 创建任务

在“项目与任务”中新建项目，进入项目后点击“创建研究任务”。

| 任务类型 | 适合的目标 |
| --- | --- |
| 资料调研 | 检索、核对资料，整理带引用的结论。 |
| 论文综述 | 梳理研究脉络、方法、局限及开放问题。 |
| 技术对比 | 按统一维度比较方案，说明证据、取舍和适用条件。 |
| 研究方案 | 设计问题、假设、方法、评估流程和风险；拟议实验不会被当作已执行结果。 |
| 项目文档分析 | 只根据项目 PDF 回答问题，至少需要一份已就绪文档。 |

选择模型，填写具体目标和期望产出，再选择检索来源及 PDF 范围。不需要本地资料时选择“不使用 PDF”；项目文档分析必须使用已就绪的项目文档。

研究深度默认“标准”：收集候选资料后，先初筛、读取重点来源，再独立复筛、综合写作和审查结论。发现问题会补充检索或定向修订，标准模式最多修订一轮，深入模式最多两轮；快速模式适合基础资料整理。各阶段共用同一份预算。

任务详情中的“资料筛选与审稿”默认折叠，展开后可查看来源链接、初筛与复筛理由、引用原文和审稿意见。未读到正文、内容截断或发表日期不明都会标明；审查未通过时保留带提示的草稿。旧任务沿用提交时的处理方式，不会自动重跑。

预算支持滑条和数字框同步调整。新任务总 Token 预算上限默认为 500000，可按需要调低；预算限制资源用量，不是固定金额，最后一次模型响应可能超过 Token 阈值。

确认可能产生的费用后提交。任务会依次进行规划、执行、审核和必要的修订，任务详情可查看过程、引用、最终输出，并导出 Markdown。

旧的固定数字识别训练入口已移除。历史任务和产物保留供查看，不需要重新准备训练数据才能使用上述任务。

## 项目证据库

项目详情中的“项目证据库”保存已通过资料审查的研究结论、原文引文与来源链接。同一项目的新任务默认启用“复用本项目已有证据”，会重新筛选原始资料，并为缺口补充检索；创建任务时也可以关闭。

证据充分且仍在复核期限内时，可以减少外部检索；“最新”等时效目标仍会检索新资料。不同项目互不共享，PDF 也遵守本轮选择范围。快速模式可以使用已有证据，但自身结果不会自动成为已审查成果。

在证据库中可搜索、按来源筛选、查看贡献目标，移除或恢复条目，并调整网页和论文的复核期限。默认分别为 7 天和 30 天；复用不会刷新资料取得时间。删除原目标、项目或 PDF 后，相关成果停止供后续任务复用，已有报告保留。

已有成果可点击“整理历史成果”分批导入：完整通过审查的结果进入证据库，其余标为“待复核”，不会直接供新任务使用。浏览、导入和本地建索引不调用付费模型或检索接口。任务详情中的“项目证据复用”可查看本轮找到和采用的成果。

## 使用 PDF

在项目中上传 PDF，等待状态变为“已就绪”。首次使用需要下载本地检索模型，文档处理服务应保持运行。

默认支持单文件最多 50 MiB、500 页。扫描件与加密 PDF 不受支持。引用是否充分仍需结合原文核查。

## 用量统计

顶部 Dock 的“用量统计”支持按模型或 API 配置查看调用次数、输入/输出 Token、已确认总 Token、每日趋势和明细。可选择最近 7、30、90 天或全部时间，日期按 UTC+8 划分，页面每 15 秒更新，也可手动刷新。

统计从启用用量记录后开始，旧任务的用量仍在任务详情中。未返回用量或中断的调用单独标记，不推算为零消耗，也不会自动重发。这里是工作台内的使用记录，不代表服务商账户账单。删除任务不会清除已记录的用量。

缓存复用和研究阶段用量也可在这里查看。缓存命中的输入已包含在总输入中，仍占用任务 Token 预算；服务商未返回缓存明细时显示“未提供”。资料和提示前缀会尽量复用，实际命中取决于模型服务，不能保证。

设置单价后，可查看已确认调用的模型费用估算。人民币和美元分别汇总，不做汇率换算，也不含检索费用。价格或用量不完整的调用会单独标记；缓存与普通输入单价不同时，缺少缓存明细的调用也不估算。

## 暂停、取消与停止服务

关闭网页不会停止后台任务。如需停止执行，先在任务中暂停或取消。存在结果待核对的调用时，先查看执行记录，避免重复提交。

任务完全停止后可删除单个研究目标或项目。历史未完成的旧任务如不能继续执行，可以取消后重新选择当前任务类型和模型创建任务。

停止后台服务：

```powershell
docker compose down
```

不要添加 `-v`，以保留数据卷。手动启动的前端可按 `Ctrl+C` 停止；一键启动的前端进程记录在 `data/launcher/workbench.json`。Docker 的安装与数据位置保持在 D 盘。

## 常见问题

| 情况 | 处理方式 |
| --- | --- |
| 工作台打不开 | 重新运行启动器，确认端口 5173 可用。 |
| 后台连接失败 | 运行 `docker compose ps -a` 检查服务，再点击页面上的“重试连接”。 |
| 无法提交任务 | 在模型管理中添加并启用模型，确认其接口支持原生工具调用；文档分析还需要已就绪的 PDF。 |
| 模型超时或调用结果待核对 | 查看已有结果和调用记录；不要连续新建同一个任务。 |
| 论文检索限流 | 稍后重试，配置独立论文检索密钥，或使用已配置的网页检索。 |
| 报告证据不足 | 缩小目标、补充时间范围、提供项目 PDF，并核查原文。 |

研究报告和引用需要人工核查。请遵守模型服务和资料来源的使用条款，不要向不受信任的模型服务提交敏感资料。
